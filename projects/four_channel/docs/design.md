# 设计思路

## 1. 问题背景

在双通道记录链路基础上扩展四路独立 SPI 接入、记录 FIFO、公平仲裁、块封装和主机读出。

## 2. 总体架构

```text
RX0/RX1/RX2/RX3 -> 4x SPI/FIFO -> record mux -> block ping-pong -> FMC
```

## 3. 模块划分

| 模块 | 职责 | 输入 | 输出 | 时钟/复位 |
|---|---|---|---|---|
| 四路采集核心 | SPI 事务、CRC、记录解析 | 四路 RX | 四路 record | PL 时钟 |
| FIFO/公平仲裁 | 背压与通道隔离 | record | 汇聚 record | PL 时钟 |
| block/ping-pong | 块头、CRC、ACK、缓存 | record | host/FMC | PL 时钟 |

## 4. 关键设计决策

- 四路通道身份必须显式保留。
- 一路停顿不能造成其他通道无界等待。
- 现有工程是 ZYNQ 数字原型，后续高云迁移另行建立目标约束。

## 5. 时序、CDC 和复位

四路共用 PL 时钟；外部 SPI 和 FMC 输入输出延迟需在目标器件上重新约束。

## 6. 资源和功耗考虑

当前四通道基线约 14,177 LUT6、28,360 FF、50 个 Xilinx BRAM Tile、DSP=0。该数据不等同于高云综合结果。

## 7. 风险与未决问题

- [ ] 四路 CH1–CH3 物理球位和 Bank
- [ ] 高云目标综合/布局布线
- [ ] 四路真实板测和共同采样时基
