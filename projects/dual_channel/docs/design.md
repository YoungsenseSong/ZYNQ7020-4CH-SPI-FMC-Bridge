# 设计思路

## 1. 问题背景

在单通道 SPI/FMC 桥基础上增加第二个独立 SPI 接收通道，并保留通道身份、FIFO、记录仲裁、块封装和 F730 输出。

## 2. 总体架构

```text
RX1 -> SPI0 -> FIFO0 --+
                       +-> record mux -> block builder -> FMC/F730
RX2 -> SPI1 -> FIFO1 --+
```

## 3. 模块划分

| 模块 | 职责 | 输入 | 输出 | 时钟/复位 |
|---|---|---|---|---|
| 两路 SPI 控制器 | 独立 PEEK/COMMIT | RX1/RX2 | 记录 | PL 时钟 |
| 双 FIFO/仲裁 | 通道隔离和公平服务 | 记录 | 汇聚记录 | PL 时钟 |
| block builder/FMC | 块 CRC、所有权、主机读出 | 记录 | FMC | PL 时钟 |

## 4. 关键设计决策

- CH0/CH1 逻辑身份固定为 RX1/RX2。
- 同源双接收只作为后端和通道隔离演示。
- TX2 独立 RF 不因数字工程构建通过而自动通过。

## 5. 时序、CDC 和复位

两路 SPI 事务在同一 PL 时钟下仲裁；FMC 地址/数据窗口单独约束。

## 6. 资源和功耗考虑

双通道工程是当前四通道扩展的中间验证入口；资源、时序和引脚不能直接外推到高云。
